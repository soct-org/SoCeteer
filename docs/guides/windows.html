SoCeteer on Windows

What differs when the development machine runs Windows. The hardware side — design generation, simulation, Vivado builds — works natively (CI builds and simulates on Windows for every change); the Linux software side needs WSL or Docker. Read this before Setting up SoCeteer, then follow that guide with the substitutions below.

1. Before cloning

The submodule tree contains paths longer than Windows' historical limit. Enable long paths once, in an administrator PowerShell, before the clone:

Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name 'LongPathsEnabled' -Value 1
git config --system core.longpaths true

Clone into a short path (e.g. C:\s\SoCeteer): generated file names are deep, and Verilator builds can otherwise hit the command-line length limit.

2. Packages

choco install cmake ninja dtc-msys2 winflexbison3

Plus Java and SBT (choco install sbt, or let IntelliJ provide both) — and, for simulation only, Visual Studio (builds Verilator) and MinGW (builds the simulator).

3. What works, what differs

AreaOn Windows
Design generation Works natively; same launcher commands.
Bare-metal programs Work natively; the RISC-V toolchain is fetched automatically.
Simulation Works natively with Visual Studio and MinGW installed. A command-length error during the Verilator build means the project path is too long — move it, or pass --single-verilog-file to the launcher.
Vivado builds Work natively, including the detached vivado.syn/vivado.bs builds; the printed follow and kill commands are PowerShell (Get-Content -Wait, taskkill).
Remote development Works as the local side when ssh and rsync are on the PATH (Windows ships OpenSSH; rsync comes with MSYS2 or Git for Windows SDK). The build server itself must run Linux or macOS — a Windows remote is refused, since the detached build needs a POSIX shell there.
Linux world (binaries/linux) Not supported natively — the kernel build needs a GNU host. Use WSL2 or Docker (below).

4. WSL2 and Docker

A WSL2 distribution counts as a Linux host: everything in the other guides, including the Linux world, works inside it with the Linux instructions as written. The prebuilt Docker image (see the README) carries every host dependency and is the quickest route to a Linux-world build on a Windows machine.
